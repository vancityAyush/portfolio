# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## What this repo is

Two loosely coupled things live side by side:

1. **A static personal portfolio site** — hand-written HTML at the repo root (`index.html`, `about.html`, `work.html`, `contact.html`) plus per-project case studies in `works/`. No build step, no package manager, no bundler.
2. **A LaTeX resume pipeline** — `.tex` sources in `src/resume/`, structured career data in `data/`, and an AI agent definition that tailors resumes to job descriptions.

## Resume build

XeLaTeX only (not pdflatex — the templates use `fontspec`). All output goes to `dist/resume/` (gitignored).

```bash
make check                                    # verify xelatex is installed
make all                                      # build every .tex in src/resume/
make main                                     # build just main.tex
make pdf FILE=src/resume/google-sde2-resume.tex   # build one arbitrary file
make watch                                    # fswatch-driven auto-rebuild
make clean                                    # remove .aux/.log/etc, keep PDFs
```

`make clipboard-health` and several steps in `.github/workflows/latex-build.yml` reference `.tex` files that no longer exist in `src/resume/` (only `main.tex` and `resume.tex` remain). Those CI steps are marked `continue-on-error`, so the workflow still passes; the Makefile target will fail. Don't assume a target's inputs exist.

CI (`.github/workflows/latex-build.yml`) only fires on pushes touching `src/resume/**/*.tex`.

## Resume data flow

`data/` is the single source of truth for resume content — never invent facts that belong there.

- `data/resume/*.json` — canonical profile, experience, education, skills, certifications, projects.
- `data/github/` — scraped GitHub stats. `index.json` is the roll-up; `repos/<name>/metadata.json` and `activity.json` hold per-repo commit/PR numbers used to quantify resume bullets.
- `data/linkedin/` — manually maintained (LinkedIn blocks scraping), so it drifts. Prefer `data/resume/` when the two disagree.

A tailored resume is generated by reading `data/resume/*.json` + `data/github/`, copying `src/resume/main.tex` verbatim, and substituting **only text content** — never the preamble, `\usepackage` lines, `tabularx`/`minipage` structure, `itemize` options, `\color[HTML]{...}` codes, or `\\[Npt]` spacing. Output naming: `src/resume/{company}-{role}-resume.tex`.

The full behavioral spec lives in `.github/agents/Resume-Builder.agent.md` and `.agent/workflows/tailor-resume.md`. Read both before touching resume generation — they encode ATS rules (skills section at top, XYZ bullet formula, keyword frequency) that aren't obvious from the `.tex` files.

## Portfolio site

Open the `.html` files directly or serve the repo root with any static server (`python3 -m http.server`). There is nothing to compile.

Architecture worth knowing before editing:

- **CSS and most JS are loaded from `https://dennissnellenberg.com/assets/...`** — an external origin this repo does not control. There is no local stylesheet. Changing site styling means either overriding inline or vendoring those files locally first.
- **Barba.js drives page transitions.** Every page has `data-barba="wrapper"` → `data-barba="container"` with a `data-barba-namespace`: `home`, `about`, `work`, `contact`, and `work-single` for everything in `works/`. The remote `index-new.js` keys animations off these namespaces, so a new page must declare one of them.
- GSAP + ScrollTrigger, locomotive-scroll, and vanilla-lazyload are pulled from CDNs at the bottom of each page.
- Several `<meta>`/`og:` tags and the `<link rel="canonical">` still point at `dennissnellenberg.com`. Fix these when touching page `<head>`s.

`components/` holds unreferenced HTML fragments — scratch snippets, not an include system. Nothing loads them.

`assets/` is organized per-project (`assets/crop-secure/`, `assets/healthflex/`, …) matching the pages in `works/`.
